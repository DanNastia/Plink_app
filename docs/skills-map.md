# Карта ролей Plink

Основной маршрут новой функции: аналитик → архитектор → дизайнер → разработчик → тестировщик → ревьюер → авторы проекта (решение по PR). Для исправления ошибки можно начать с воспроизведения у тестировщика. Для изменения документации ревьюер проверяет документы напрямую.

| Роль и инструкция | Что получает | Что передаёт |
|---|---|---|
| [Аналитик](../.agents/skills/plink-analyst/SKILL.md) | Интервью, Excel, решения авторов | Архитектору — требование и критерий приёмки в docs/requirements.md |
| [Архитектор](../.agents/skills/plink-architect/SKILL.md) | Требование и ограничения проекта | Дизайнеру и разработчику — модель, формулы и состояния в docs/architecture.md |
| [Дизайнер](../.agents/skills/plink-designer/SKILL.md) | Сценарий и допустимые состояния | Разработчику — описание экрана и поведения в docs/design.md |
| [Разработчик](../.agents/skills/plink-developer/SKILL.md) | Согласованные документы или воспроизводимая ошибка | Тестировщику — изменения в app/ и шаги запуска в журнале |
| [Тестировщик](../.agents/skills/plink-tester/SKILL.md) | Ветка с изменениями и критерии приёмки | Ревьюеру — фактические результаты в docs/test-report.md, при сбое разработчику — шаги воспроизведения |
| [Ревьюер](../.agents/skills/plink-reviewer/SKILL.md) | Изменения ветки, требования и результаты проверок | Авторам — заключение в docs/agent-log.md и PR, исполнителю — замечания для исправления |

Указанные файлы дизайна и проверок создаёт соответствующая роль при первой задаче. При возврате укажите вопрос и раздел файла в журнале. За смыслом требования обращайтесь к аналитику, за изменением расчёта — к архитектору, за уточнением экрана — к дизайнеру. После исправления тестировщик повторяет затронутые проверки, ревьюер сверяет новую версию ветки.
