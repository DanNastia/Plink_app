# Plink. Архитектура первой версии

Одна страница React и одно состояние в App через useState. Vite запускает проект в разработке и собирает статические файлы. Браузер выполняет расчёты локально. Для курсового проекта достаточно четырёх частей.

| Часть | Ответственность |
|---|---|
| App и небольшие компоненты форм, журнала, сводки и диаграммы | App принимает действия пользователя. Компоненты получают значения и обработчики через props. Черновик покупки живёт в форме |
| finance.js | Чистые функции проверки суммы и расчёта баланса, резерва, лимита, прогноза и сумм по категориям. Сегодняшняя дата передаётся аргументом для воспроизводимых проверок |
| storage.js | Чтение, проверка структуры и запись одного объекта JSON по ключу plink.v1 |
| App.css и index.css | Обычный CSS. На узком экране блоки располагаются в одну колонку. Диаграмму можно построить полосами CSS, рядом вывести текстовые значения |

## Что хранить

| Поле | Содержимое |
|---|---|
| nextIncomeDate | Локальная календарная дата в формате YYYY-MM-DD или null |
| transactions | Массив фактических операций. У каждой уникальный id, type (income или expense), amountKop, date, categoryId и строка comment |
| obligations | Массив обязательных расходов. У каждого уникальный id, название title, amountKop, dueDate, categoryId и paidTransactionId. До оплаты ссылка равна null, после оплаты содержит id расхода |

Категории — постоянный список в коде с уникальным id, названием и типом операции. Суммы хранятся положительными целыми числами в копейках, направление задаёт type. Даты операций не позже сегодняшней. Для суммы принять цифры с необязательной запятой или точкой и одной или двумя дробными цифрами. Разобрать рубли и копейки отдельно. Отклонить ноль, знак, экспоненту, текст и значения, при которых сумма или денежный итог выходит за диапазон безопасных целых JavaScript. Проверять существование даты, тип категории и ссылки до сохранения.

Если ключ `plink.v1` отсутствует, оба массива пусты, дата равна null. При загрузке существующей записи проверить структуру после разбора JSON. Каждая заполненная ссылка `paidTransactionId` должна вести к фактическому расходу с суммой и категорией этого обязательства. Один расход может подтверждать оплату только одного обязательства. При каждом изменении App формирует новое состояние, проверяет его и записывает целиком, затем обновляет экран. При отказе записи показать причину и сохранить ввод для повтора. При ошибке чтения, разбора JSON или проверки структуры и связей показать сообщение и заблокировать запись поверх сохранения. Данные доступны в одном браузере для одного адреса приложения. Расчётные итоги и прогноз пересчитываются из записей.

## Финансовые правила

Все денежные формулы используют копейки. Пусть T — сегодняшняя дата по местному календарю, N — дата следующего дохода.

1. Баланс B = сумма всех доходов − сумма всех фактических расходов. Отрицательный результат показывается со знаком.
2. Если N отсутствует или N ≤ T, показать баланс и список обязательств, предложить выбрать будущую дату. До выбора будущей даты резерв за период, свободные средства, дефицит, лимит и прогноз показываются как недоступные. Журнал и диаграмма за текущий месяц остаются доступны. Сохранённая дата в прошлом или на сегодня допустима при загрузке. Её наступление само по себе не создаёт операцию дохода. Когда вкладка открыта в полночь или вновь получает фокус, обновить T.
3. Число дней D = календарная разность N и T. Сегодня включено, день поступления исключён. Для подсчёта использовать номера календарных дней, например UTC по отдельным компонентам года, месяца и дня. Так переход часов не меняет число дней.
4. Резерв R = сумма обязательств с пустой ссылкой на оплату и dueDate < N. Нижней границы нет: просроченные обязательства ещё предстоит оплатить. Платежи со сроком N и позже остаются в списке на будущее.
5. Доступные средства F = B − R. Дефицит = max(0, −F). Дневной лимит L = floor(max(0, F) / D). Округление вниз оставляет остаток копеек в бюджете. Например, 100 ₽ на три дня дают 33,33 ₽ в день.
6. Для дополнительной покупки ценой P применить те же формулы к F − P и тому же D. Показать оба лимита и оба дефицита. Использовать тот же разбор суммы, что и для расхода. Изменение или закрытие прогноза влияет только на черновик формы. Если покупка превышает свободные средства, новый лимит равен нулю и видна сумма нехватки.
7. Для диаграммы отобрать фактические расходы с годом и месяцем T, сложить суммы по categoryId. Доля = сумма категории / сумма выбранных расходов × 100%. При нулевой сумме показать пустое состояние до деления.

## Как провести оплату один раз

Пользователь открывает обязательство и выбирает «Оплатить». Обработчик находит его по id в актуальном состоянии и проверяет paidTransactionId. Если ссылка заполнена, повторная команда ничего не меняет. Иначе обработчик создаёт расход на полную сумму с датой T и категорией плана и проставляет его id в обязательстве. Обе записи сохраняются одним вызовом `window.localStorage.setItem` для общего объекта. Публиковать новое состояние в App только после успешной записи. При ошибке обязательство остаётся неоплаченным, и оплату можно повторить. Оплаченный план исключается из резерва. Для платежа из резерва баланс и резерв уменьшаются на одинаковую сумму, свободные средства сохраняются. Форму обычного расхода для этой оплаты пользователь не заполняет. Отмена неоплаченного плана удаляет только план.
