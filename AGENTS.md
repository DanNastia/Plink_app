# Работа над Plink

Авторы проекта — Данилова Анастасия и Козубенко Мария. На проект отведено пять дней по 2–4 часа в день на участницу. Выбирайте задачи, которые можно выполнить и проверить за одно занятие. Ответственную участницу указывайте по фактической договорённости.

## Перед началом

1. Прочитайте задание, техническое задание в `docs/requirements.md`, архитектуру в `docs/architecture.md` и последние записи по задаче в `docs/agent-log.md`. Проверьте текущую ветку, изменения и входные файлы.
2. Выберите роль по [карте скиллов](docs/skills-map.md) и прочитайте её SKILL.md. Используйте один идентификатор на всём пути задачи, например PLINK-<номер>. Начинайте с роли, которой принадлежит текущий вопрос.
3. Работайте в отдельной ветке от актуальной main. Сохраняйте материалы других участниц. Меняйте только файлы, нужные для задачи.

## Ограничения проекта

Стек — React, JavaScript, Vite, обычный CSS, LocalStorage и Recharts для диаграммы. Исходники находятся в app/. Новые зависимости сверх согласованного стека требуют решения авторов. Сервер, регистрацию и внешние API проект не предусматривает. Пишите инструкции на русском, выбирайте решения, которые обе участницы смогут объяснить на защите.

Считайте согласованное ТЗ основанием для реализации. Изменение требований предложите авторам в PR с обоснованием и влиянием на проверки. Пустое интервью, предположение модели и ожидаемый результат теста не являются наблюдениями.

## Передача и приёмка

Codex работает с GitHub через веб-интерфейс. Для Qwen3.5:4b участница передаёт локально текст скилла и нужные входные файлы, сверяет ответ и переносит результат в ту же ветку. В VS Code запускайте команды из терминала в app/, сверяясь с package.json. Указывайте, какая модель и какое окружение действительно использовались.

Результат передавайте через файлы ветки. Добавляйте по одной строке на завершённый этап в [журнал](docs/agent-log.md), указывайте путь к результату и следующую роль. При возврате сохраняйте историю и используйте тот же идентификатор. Одна задача может пройти несколько ролей в одном PR. В описании PR перечислите задачу, изменённые файлы, фактические проверки и открытые вопросы. Слияние в main выполняют авторы после просмотра изменений.
